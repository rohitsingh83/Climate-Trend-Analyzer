# Contributing

Thanks for your interest in improving the Climate Trend Analyzer! This guide explains how to
work on the project without breaking it.

---

## Getting set up

```bash
git clone https://github.com/your-username/Climate-Trend-Analyzer.git
cd Climate-Trend-Analyzer
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
pip install pytest
pytest -v
```

---

## The golden rule

> **Never edit anything under `outputs/` by hand.**
> Every figure, table and report in that folder is generated by the pipeline.
> If you want to change one, change the code that produces it and re-run:

```bash
python main.py --step all
```

---

## Branching

```bash
git checkout -b feature/new-anomaly-method      # a new branch
git add -A
git commit -m "feat(anomalies): add a rolling-window detector"
git push -u origin feature/new-anomaly-method
# open a Pull Request on GitHub
```

Branch names: `feature/...`, `fix/...`, `docs/...`, `refactor/...`.

---

## Commit message convention

```
<type>(<scope>): <short imperative description>

<optional body explaining WHY, not WHAT>
```

| Type | Use for |
| --- | --- |
| `feat` | a new feature (new detector, new chart, new model) |
| `fix` | a bug fix |
| `docs` | documentation only |
| `refactor` | code change with no behaviour change |
| `test` | adding or fixing tests |
| `perf` | performance improvement |
| `chore` | dependencies, tooling, housekeeping |

Examples:

```
feat(forecasting): add a seasonal-naive baseline to the model comparison
fix(trend): correct the sign of the Mann-Kendall S statistic
docs(readme): add the model-comparison table and the results section
test(preprocessing): assert that impossible values never survive cleaning
```

## Pull request checklist

- [ ] `pytest -v` passes locally (26 tests)
- [ ] `python main.py --step all` runs without errors
- [ ] New code is commented and follows the existing style
- [ ] New behaviour has a test
- [ ] Documentation updated (`docs/`, README) if behaviour changed
- [ ] The PR description explains **what** and **why**

---

## Style guide

* **Type hints** on public functions (`def foo(x: pd.DataFrame) -> dict:`)
* **Docstrings** at the top of every module explaining *what it does and why*
* **Comments** that explain *why*, not *what* - the code already says what
* Keep functions short; if one exceeds ~60 lines, split it
* Use `config.py` for any new threshold or path - never hard-code a number twice
* Prefer `pathlib.Path` over string paths

## Adding a new feature - a worked example

**Goal:** add a new anomaly detector based on a rolling z-score.

1. **Write the function** in `src/anomaly_detection.py`:

```python
def rolling_z_anomalies(df: pd.DataFrame, window: int = 12,
                         threshold: float = 2.5) -> pd.DataFrame:
    """Flag months far from their own local rolling baseline."""
    rows = []
    for region, grp in df.groupby("region"):
        g = grp.sort_values("date")
        roll_mean = g["temp_mean_c"].rolling(window, center=True, min_periods=6).mean()
        roll_std = g["temp_mean_c"].rolling(window, center=True, min_periods=6).std()
        z = (g["temp_mean_c"] - roll_mean) / roll_std
        for (_, r), zi in zip(g.iterrows(), z):
            if pd.notna(zi) and abs(zi) >= threshold:
                rows.append({...})          # same schema as the other detectors
    return pd.DataFrame(rows)
```

2. **Register it** in `detect_anomalies()` (add it to the `parts` list).
3. **Add a test** in `tests/test_pipeline.py`.
4. **Run** `pytest -v` and `python main.py --step all`.
5. **Update the docs**: `docs/METHODOLOGY.md` (the detectors table) and the README.

## Reporting bugs

Open an issue with:
* what you did, what you expected, what happened
* your OS, Python version (`python --version`) and package versions (`pip list`)
* the smallest snippet that reproduces the problem
* the full traceback, not a screenshot of it

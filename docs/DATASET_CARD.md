# Dataset card — two explicitly separate tracks

## 1. Synthetic regional panel

**Origin:** `src/data_generator.py`, seed 42. **Use:** teaching, regression tests, workflow demonstration. **Not for:** scientific, policy, financial or safety decisions. The simulation is not calibrated to observed city climatology.

**Coverage:** January 1980–December 2024, five cities, 540 months each. 2,700 base observations; raw file has 2,715 rows including 15 deliberate duplicate keys. Cities: Hyderabad, London, New York, Singapore and Sydney. Different hemispheres have different warm-season peaks.

| Field | Meaning / unit |
| --- | --- |
| `date` | Month start; raw contains ISO and explicit US-format strings |
| `region`, `country` | Illustrative city and country labels |
| `latitude`, `longitude` | Approximate coordinates in decimal degrees |
| `temp_mean_c` | Synthetic monthly mean temperature, °C |
| `temp_min_c`, `temp_max_c` | Illustrative means of daily minima/maxima, °C; not absolute annual records |
| `rainfall_mm` | Synthetic monthly precipitation total, mm |
| `humidity_pct` | Synthetic mean relative humidity, % |
| `co2_ppm` | Illustrative global-like concentration with regional offsets; NOT local measured CO₂ |
| `sea_level_mm` | Illustrative global-like series relative to synthetic 1980 level; not measured city sea level |
| `sim_heatwave` | Explicit label for planted +4.5°C monthly stress episodes |
| `sim_drought` | Explicit label for planted 85% rainfall reductions |
| `year`, `month` | Calendar fields added by cleaning |
| `observed_temp_mean_c` | Pre-imputation target; missing/invalid observations remain NaN for honest forecast evaluation |
| `data_quality_flag` | `original` or `repaired`; assigned before sorting to preserve row alignment |

**Defects:** 1.5% missing entries in each of three measurement columns, 15 duplicates, 12 impossible mean temperatures and 10% mixed date strings. Core measurement completeness becomes 100% after historical interpolation; preserved observations and lag/change features intentionally retain some NaNs. A zero missing count for all engineered columns is neither expected nor desirable.

**Files:** `data/raw/climate_raw.csv`, `data/processed/climate_clean.csv`, `data/processed/climate_featured.csv`. Data and code generated by this project are released under MIT. Dataset size is intentionally small; do not claim large-scale distributed processing.

## 2. Real public CO₂ companion

**Source:** NOAA Global Monitoring Laboratory / Scripps, Mauna Loa monthly atmospheric CO₂.

- Landing page: https://gml.noaa.gov/ccgg/trends/data.html
- Direct source: https://gml.noaa.gov/webdata/ccgg/trends/co2/co2_mm_mlo.csv
- Attribution requested by source: Dr. Xin Lan, NOAA/GML and Dr. Ralph Keeling, Scripps Institution of Oceanography.
- Original source: `data/raw/noaa_co2_mm_mlo.csv` (including comment headers and usage notes).
- Retrieval/URL/SHA256: `data/raw/noaa_provenance.json`.
- Analyzed period: January 1980–December 2024, 540 monthly rows, 45 complete annual means.
- Unit: **concentration in ppm, not emissions**.
- The full cached source contains additional dates; the analysis deliberately keeps a completed common period. Source revisions can change historical figures after `--refresh`.
- Source notes describe measurement-site interruption and interpolated months. These remain qualifications of the data; no independent ground-truth verification is claimed.
- External observations retain their source terms/attribution. The project license does not relicense them as project-generated synthetic data.

**Files:** `data/processed/noaa_co2_monthly.csv`, `outputs/tables/noaa_co2_annual.csv`, `outputs/noaa_summary.json`, `outputs/figures/16_public_noaa_co2.png`.

**Offline:** `python -m src.public_data`. **Explicit refresh:** `python -m src.public_data --refresh`. Failed refresh raises an error; it never substitutes fabricated measurements.

## 3. Real-data replacement is an adapter task

Do not simply rename a global temperature-anomaly CSV to the full multi-variable synthetic schema. Real datasets differ in spatial scope, cadence, baseline and units. Add a source-specific adapter that:

1. preserves source provenance and license;
2. maps only actually available measurements, without fabricating humidity/rainfall;
3. defines units, calendar, baseline, coordinates and coverage;
4. rejects duplicate/conflicting keys and missing required variables;
5. calls only analyses supported by the source and documents limitations.

The shipped NOAA companion is an example of **separate, source-appropriate analysis**, not a claim that any CSV is a drop-in replacement for seven climate indicators.
